# 第三问：远端延长搜索与算法复核补充

本文件补充记录四份 Agent 和 `method.txt` 复核后的远端搜索。四份旧实现只提供候选生成、连续通信检查、路线结构多样化和 ALNS 式邻域等思路；旧结果中的中继同步、离散采样和物理口径问题没有直接继承。当前正式算法仍是“候选结构生成＋连续通信证书＋CP-SAT 联合排程＋独立验证”。

## 远端试验

在用户授权的 `xjz@10.33.12.63`（`xjz-desktop`）上运行 Python `3.10.21`、OR-Tools `9.15.6755`，使用 8 个 CP-SAT worker、65 个站点、1200 条活动候选上限、4 轮各 120 秒联合邻域和 120 秒固定结构精修。CP-SAT 主要由 CPU 求解，RTX 3090 没有直接参与 CP-SAT 计算。

| 指标 | 正式方案 | 远端候选 | 远端减正式 |

| 运输／中继架次 | 21／3 | 21／3 | 0／0 |
| 运输能耗/kWh | 64.09596908039461 | 64.09596908039461 | 0 |
| 中继能耗/kWh | 2.349304202173859 | 2.349304202173859 | 0 |

正式方案的独立验证为 11884 项、0 错误；远端候选为 11902 项、0 错误。两者均通过 240 个连续通信区间，未证明区间为 0，最小连续通信裕量为 `0.07973598524506542 dB`，期望时限迟到为 0。完整哈希和字段见 [远端搜索摘要](远端搜索摘要.json)。

## 采用决定

远端方案的评分改善只有 `6.37×10^-8`，低于当前 `1e-6` 解释界限；联合完工只提前 1 ms，能耗、架次和通信证书没有变化，加权平均交付反而晚约 8.18 s。因此保留 [正式方案](solution_recommended.json) 和 [正式验证](validation_recommended.json)，远端结果只作为历史候选，不替换正式 JSON、Excel、审计哈希或原有上传清单中的正式数值。

如果继续追求结构性改善，应实现允许中继多次出勤的联合列生成或带连续证书回调的 ALNS，并继续用独立验证器筛选；单纯增加 CP-SAT 时间没有显示出新的结构收益。

本次补充只新增本目录说明和摘要，不修改师兄工程；已上传的独立第三问目录与正式结果保持不变。
