# 第一问货箱组批程序

从项目根目录执行：

```powershell
python -m pip install -r code/requirements_q1.txt
python code/solve_q1_batching.py
python code/verify_q1_local_plane.py --geometry-only
python code/solve_q1_multiobjective.py
python code/solve_q1_reserve_sensitivity.py
python code/verify_q1_local_plane.py
```

使用已安装依赖的 Python 解释器：

```powershell
python code/solve_q1_batching.py
```

程序会优先查找项目 `.runtime_py` 中的额外依赖。也可以在独立虚拟环境安装 `requirements_q1.txt`。所有原始 Excel、DOCX 和 DEM 只读；默认输出目录为 `results/question1_batching`。

上述顺序先生成基准结果，再审核其几何，随后重算多目标与敏感性，最后完成独立核验；全部通过后再执行三个 Excel 导出程序。几何审核绑定 `solution_sha256`，基准结果记录 `solver_sha256`；修改基础求解器后，必须重新生成基准及几何审核，再重新生成后两小项，不能沿用旧文件的“已通过”状态。

局部椭球平面的距离与直线栅格求交直接计算，当前依赖不再要求 `pyproj`，也不再使用旧版 `--terrain-step-m` 参数。

程序采用基准 20% 返航余量，按“最少架次、最低总能耗、最短累计作业时间”的字典序选取组批方案。适用范围仅为问题一，架次编号不表示具体执行顺序，不分配实体无人机或共享电池，不检验问题二的时限与资源调度。

能耗模型的水平与爬升分项是已经明示的补充解释：

```text
L(q) = L0 - (L0-LF)*(q/Q)^1.5
E(q) = Euse*d*(1/L(q)+1/L0)
       + 9.80665*((m0+q)*a+m0*b)/(eta*3.6e6)
```

距离用 m，质量用 kg，能耗用 kWh；m0 已包含电池。原题没有展开两个能耗分项，也未指定重力加速度数值，本次按用户要求统一取标准重力 `g0=9.80665 m/s²`，不是原题强制值或当地实测值；若后续取得官方澄清，应修改对应函数后重新计算。

## 数值计算与目标比较

连续载荷二分返回可行侧下界，区间精度为 `1e-6 kg`；常规能量可行性容差为 `1e-9 kWh`。每个候选分别计算 `round(E*1e12)` 与 `round(T*1e6)`，状态转移累加这两个整数，字典序与非支配判断均比较整数成本；不能改为每次累加浮点总成本后再四舍五入。可行性检查及输出汇总使用未量化成本。完整 Pareto 非支配动态规划与全部临界事件扫描均保留，事件比较使用 `RHO_TOL=1e-10` 个百分点，六种完整目标排序均输出。

## 当前坐标与版本口径

第一问现采用以 O01（109.2308517°E、23.0085095°N）为固定原点的 WGS84 局部椭球平面坐标。椭球参数为 `a=6378137 m`、`e2=6.6943799901413165e-3`，全部经纬度先转换为弧度：

```text
N0 = a / sqrt(1-e2*sin(phi0)^2)
M0 = a*(1-e2) / (1-e2*sin(phi0)^2)^1.5
x  = N0*cos(phi0)*(lambda-lambda0)
y  = M0*(phi-phi0)
d  = hypot(x,y)  # O01 到服务区的单程水平距离，m
```

所有节点采用同一原点和固定尺度系数。地形取高程使用同一局部平面直线对应的经纬度直线，完整遍历相交 DEM 像元；PixelIsPoint 中心注册的 `+0.5` 偏移、接触边界与角点均纳入、最高地形加 50 m 等规则保持一致。原题未强制指定 UTM 或局部椭球平面，本次按统一计算口径选择后者。原始 TIFF 点标签下的半像元处理不能对 GIS 库已经校正为角点的变换重复执行。附件的最大爬升、最大下降速度作为相应阶段的恒定速度，未另计加减速。

2026-09-24 改版前的 UTM 代码、文档及结果完整备份于 `archives/question1_utm_before_local_plane_20260924.zip`。该归档仅供历史对照和回退；当前三个结果目录与 Excel 均以局部椭球平面重算版本为准。

`solution.json` 保存全部输入指纹、原始箱号、航线像元、批次和汇总；`Q1_单点组批.csv` 采用题目 Q1 表头，UTF-8 BOM 编码。模板中的“往返时间”在本次输出约定为纯飞行时间，含准备、装载与交接的作业时间单独记录于 JSON/Excel 明细中。

同目录的 `Q1_局部椭球距离与航线.csv` 给出 15 条 O01 至服务区的路线；`Q1_局部椭球有向航段.csv` 给出去返共 30 条航段，`start/end/distance/cruise_altitude/climb/descent` 可供接入，长度字段均为 m。`distance` 为单程水平距离，不是空间斜距；返程的爬升、下降与去程对调。上述表仅覆盖第一问的辐射航线，不含服务区之间的航段。

独立审核不调用主求解器：地形审核独立计算局部尺度，并将经纬度直线与每个候选闭像元矩形做线段裁剪；基准与多目标审核重新从原始工作簿读取数据，采用 40 位 Decimal 物理成本与逐箱位掩码非支配动态规划，核对完整 Pareto 前沿和真实箱号可行性。敏感性审核另用独立数量状态动态规划扫描所有候选临界区间与端点，并重新检查每套代表方案的真实箱号。

## Excel 导出

Excel重导需要Node.js及 `@oai/artifact-tool`；原本机依赖联接未上传。依赖就绪且求解完成后执行：

```powershell
node code/export_q1_batching.mjs
```

默认生成 `outputs/question1_batching/第一问_货箱组批方案.xlsx`，以及用于显示检查的 PNG 预览。导出程序只读取题目结果模板的表头并验证，不会覆盖原模板。Excel 汇总与检查公式可重算，但编辑表格不等于重新执行货箱组批优化；改变需求、机型或计算口径后应先重新运行 Python 求解器，再重新导出。

## 第一问的三目标优化小项

在上一小项的 `solution.json` 与地形审核已生成后执行：

```powershell
python code/solve_q1_multiobjective.py
```

新增输出位于 `results/question1_multiobjective`，不覆盖原组批结果。程序重新读取原始节点、机型及箱号，并核对全部原始文件 SHA-256；输入变化时会停止，要求先重新生成几何。沿用已验证的物理函数，完整枚举可行批次，逐状态保留 `(N,E,T)` 非支配标签，再合并各区前沿。每个不同目标向量保留一套具体箱号方案，等价箱号置换不重复输出。

当前数据的完整前沿有两点：18 架次、59.132260 kWh、32776.516782 s；19 架次、59.034878 kWh、34440.488752 s。后者只调整 S008。详细优先级、节能与时间代价见生成结果目录内的分析文档。

多目标 Excel 导出命令：

```powershell
node code/export_q1_multiobjective.mjs
```

生成 `outputs/question1_multiobjective/第一问_多目标优化结果.xlsx`，不会覆盖上一小项的工作簿。包含方案比较、完整前沿和代表方案批次三个工作表；编辑工作簿不会重新求解 Pareto 前沿，修改需求或参数时应重新执行上述 Python 程序。

## 第一问的返航安全余量敏感性小项

在基准 `solution.json` 和 `geometry_audit.json` 已生成后执行：

```powershell
python code/solve_q1_reserve_sensitivity.py
```

程序统一改变三种机型的余量比例，沿用 `(N,E,T)` 字典序和前述补充能耗式；核对原始输入 SHA-256，重新枚举全部742个质量/体积可行候选，包含20%基准下不安全的10个候选。通过连续载荷二分及候选临界余量事件扫描，计算45组载荷、18个典型情景和19段完整组批方案。常规对照为5%—45%每5个百分点九档，另保留零余量、局部阈值附近及更高余量情景。输出位于 `results/question1_reserve_sensitivity`，不会覆盖前两小项结果。

`sensitivity.json` 中余量字段单位为百分数，`safe_payload_kg=null` 表示空载往返也不可行，不能替换成0；不可行配送情景的目标字段也为null。区间首段为闭区间，后续均为左开右闭，等号保留前一方案。末端两个临界值35.266593693194835%和35.26764734919061%非常接近，区间仅宽0.00105365599578个百分点，不应按粗网格或显示四舍五入合并。

Excel 导出：

```powershell
node code/export_q1_reserve_sensitivity.mjs
```

生成 `outputs/question1_reserve_sensitivity/第一问_安全余量敏感性.xlsx`。详细载荷模型、典型情景、临界拆批、可行上限和指标解释见 `results/question1_reserve_sensitivity/第一问_返航安全余量敏感性分析.md`。工作簿用于展示已求解情景，编辑表格不能替代重新运行敏感性求解器。
